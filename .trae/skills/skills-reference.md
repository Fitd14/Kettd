# 技能参考表

本文档提供项目中所有可用技能的中文说明，方便快速查阅和调用。

---

## 一、TRAE 内置技能

### 1. TRAE-code-review（代码审查）

**中文描述**：用于执行代码审查任务。适用于审查合并请求、代码差异，并提供关于代码质量、正确性和最佳实践的结构化反馈。

**用途场景**：
- 审查合并请求（MR/PR）
- 审查代码差异
- 提供代码质量反馈
- 检查最佳实践遵循情况

**触发方式**：当用户提出"审查代码"、"代码审查"、"PR审查"等需求时自动触发。

---

### 2. TRAE-debugger（调试器）

**中文描述**：用于调试需要收集运行时证据的复杂问题。它会启动一个调试服务器通过 HTTP 收集日志，然后遵循科学的调试流程（假设 → 插桩 → 复现 → 分析 → 修复 → 验证）。适用于仅通过静态代码分析无法诊断的 Bug。在用户主动要求运行时调试、或经过多轮对话仍无法通过静态分析解决问题时触发。

**用途场景**：
- 调试复杂运行时问题
- 收集运行时日志证据
- 诊断仅通过静态分析无法定位的 Bug
- 需要科学方法进行假设验证的问题

**触发方式**：当用户提出"调试"、"运行时调试"、"Bug修复"等需求时自动触发。

---

### 3. TRAE-generate-mini-app（小程序生成）

**中文描述**：当用户意图涉及小程序、Taro、微信小程序、跨端小程序等任何包含小程序的意图时，用于生成基于 Taro 框架的高质量、可运行的多端小程序代码。

**用途场景**：
- 生成微信小程序
- 生成支付宝小程序
- 生成抖音小程序
- 生成跨端小程序（基于 Taro）

**触发方式**：当用户提出"生成小程序"、"创建小程序"、"开发小程序"等需求时自动触发。

---

### 4. TRAE-security-review（安全审查）

**中文描述**：用于执行代码安全扫描任务。适用于审查合并请求和代码差异，并提供关于代码安全、漏洞风险和安全最佳实践的结构化反馈。

**用途场景**：
- 代码安全扫描
- 漏洞风险检测
- SQL注入检测
- 认证/授权缺陷检测
- 加密和密钥处理检查
- 敏感数据泄露检测

**触发方式**：当用户提出"安全审查"、"代码安全"、"漏洞检测"等需求时自动触发。

---

## 二、Web 开发技能

### 5. web-artisan（Web 工匠）

**中文描述**：创建高质量、具有独特设计的生产级 Web 界面和全栈 Web 应用。此技能处理广泛的 Web 开发任务，包括：构建交互式游戏（HTML5、Canvas、JavaScript）、教育/培训网页、电商网站（B2C/C2C）、数据仪表板/可视化、实用工具（QR码生成器、计算器）、内容管理系统、3D Web 场景（Three.js/WebGL）以及从设计规范（Figma/PSD/图片）实现像素完美的 UI。生成完整、可运行的代码（HTML、CSS、JavaScript），并附带清晰的说明和生产就绪的最佳实践。当用户要求进行 Web 开发、Web 设计、创建网页/网站、前端/后端实现或将设计转换为代码时，应使用此技能。

**用途场景**：
- 创建高质量 Web 界面
- 构建交互式游戏
- 开发电商网站
- 实现数据可视化仪表板
- 创建实用工具
- 构建 3D Web 场景
- 从设计稿实现像素完美的 UI

**触发方式**：当用户提出"创建网站"、"Web开发"、"前端开发"、"网页设计"等需求时自动触发。

---

### 6. web-design-docs（Web 设计文档）

**中文描述**：构建 React 前端的完整指南，包含 PRD（产品需求文档）和技术架构模板。涵盖 3D 场景、路由、数据模型和响应式设计。

**用途场景**：
- 生成产品需求文档（PRD）
- 生成技术架构文档
- 设计数据模型
- 规划路由结构
- 设计响应式界面

**触发方式**：作为 web-artisan 技能的辅助工具，在缺少文档时自动调用。

---

### 7. web-dev（Web 开发）

**中文描述**：创建高质量设计的生产级 Web 界面。**仅当用户明确要求在空的或没有前端代码的工作区从头开始构建或创建新网站、网页、Web 应用或基于 Web 的游戏时使用此技能。** 不适用于对现有项目的 Bug 修复或修改。

**用途场景**：
- 从零开始创建全新 Web 项目
- 在空工作区中构建 Web 应用
- 创建基于 Web 的游戏

**触发方式**：当用户提出"从零开始创建网站"、"新建 Web 项目"等需求时自动触发。

---

## 三、流程管理技能

### 8. brainstorming（头脑风暴）

**中文描述**：在进行任何创造性工作（创建功能、构建组件、添加功能或修改行为）之前必须使用此技能。探索用户意图、需求和设计方案。

**用途场景**：
- 探索用户需求和意图
- 讨论设计方案
- 创意思考
- 需求澄清

**触发方式**：在进行创造性工作前自动触发。

---

### 9. test-driven-development（测试驱动开发）

**中文描述**：用于实现任何功能或修复 Bug 时，在编写实现代码之前使用。遵循测试驱动开发流程。

**用途场景**：
- 实现新功能
- 修复 Bug
- 编写测试用例

**触发方式**：在实现功能或修复 Bug 前自动触发。

---

### 10. systematic-debugging（系统化调试）

**中文描述**：用于遇到任何 Bug、测试失败或意外行为时，在提出修复方案之前使用。

**用途场景**：
- 诊断 Bug
- 分析测试失败原因
- 排查意外行为

**触发方式**：遇到 Bug 或测试失败时自动触发。

---

### 11. writing-plans（编写计划）

**中文描述**：当你有一个规范或需求来执行多步骤任务时，在接触代码之前使用。

**用途场景**：
- 编写实现计划
- 规划多步骤任务
- 制定开发路线图

**触发方式**：在执行多步骤任务前自动触发。

---

### 12. executing-plans（执行计划）

**中文描述**：当你有一个书面的实现计划要执行时使用，在单独的会话中执行并设置审查检查点。

**用途场景**：
- 执行已编写的实现计划
- 按计划推进开发任务

**触发方式**：有实现计划需要执行时使用。

---

### 13. finishing-a-development-branch（完成开发分支）

**中文描述**：当实现完成、所有测试通过，并且你需要决定如何整合工作时使用 - 指导完成开发工作，提供合并、PR 或清理的结构化选项。

**用途场景**：
- 完成开发分支工作
- 准备合并代码
- 创建 PR
- 清理开发环境

**触发方式**：开发完成并通过测试后使用。

---

### 14. requesting-code-review（请求代码审查）

**中文描述**：在完成任务、实现主要功能或合并之前使用，用于验证工作是否符合要求。

**用途场景**：
- 完成任务后请求审查
- 实现主要功能后请求审查
- 合并代码前请求审查

**触发方式**：完成任务后自动触发。

---

### 15. receiving-code-review（接收代码审查）

**中文描述**：当收到代码审查反馈时，在实现建议之前使用，尤其是当反馈看起来不清楚或技术上有问题时 - 需要技术严谨性和验证，而不是表面上的同意或盲目实施。

**用途场景**：
- 处理代码审查反馈
- 验证审查建议的合理性
- 实现审查意见

**触发方式**：收到代码审查反馈时使用。

---

## 四、协作与分发技能

### 16. dispatching-parallel-agents（并行代理分发）

**中文描述**：当面临 2 个或更多独立任务时使用，这些任务可以在没有共享状态或顺序依赖的情况下进行处理。

**用途场景**：
- 并行执行多个独立任务
- 分发无依赖的子任务

**触发方式**：需要并行处理多个任务时使用。

---

### 17. subagent-driven-development（子代理驱动开发）

**中文描述**：在当前会话中执行带有独立任务的实现计划时使用。

**用途场景**：
- 使用子代理执行实现计划中的独立任务

**触发方式**：执行有独立子任务的实现计划时使用。

---

## 五、其他技能

### 18. using-git-worktrees（使用 Git Worktrees）

**中文描述**：当开始需要与当前工作区隔离的功能工作时，或在执行实现计划之前使用 - 确保通过原生工具或 git worktree 回退存在隔离的工作区。

**用途场景**：
- 创建隔离的开发环境
- 使用 git worktree 管理多个分支

**触发方式**：开始需要隔离的开发工作时使用。

---

### 19. using-superpowers（使用超能力）

**中文描述**：在开始任何对话时使用 - 建立如何查找和使用技能的方法，要求在任何响应之前（包括澄清问题）先调用技能。

**用途场景**：
- 会话开始时初始化技能系统
- 学习如何使用技能

**触发方式**：会话开始时自动触发。

---

### 20. verification-before-completion（完成前验证）

**中文描述**：当即将声称工作已完成、已修复或已通过时使用，在提交或创建 PR 之前 - 需要运行验证命令并在做出任何成功声明之前确认输出；始终先有证据后有断言。

**用途场景**：
- 完成工作前进行验证
- 提交代码前运行测试
- 创建 PR 前确认代码正确性

**触发方式**：声称工作完成前自动触发。

---

### 21. find-skills（查找技能）

**中文描述**：当用户询问"如何做 X"、"查找 X 的技能"、"是否有可以...的技能"或表达扩展能力的兴趣时，帮助用户发现和安装代理技能。

**用途场景**：
- 搜索可用技能
- 安装新技能
- 扩展代理能力

**触发方式**：用户询问技能相关问题时自动触发。

---

### 22. skill-creator（技能创建者）

**中文描述**：创建技能的强制工具 - 当用户想要创建/添加任何技能时必须立即调用。

**用途场景**：
- 创建新技能
- 添加自定义技能

**触发方式**：用户要求创建技能时自动触发。

---

### 23. writing-skills（编写技能）

**中文描述**：用于创建新技能、编辑现有技能或在部署前验证技能是否正常工作。

**用途场景**：
- 编写新技能
- 编辑现有技能
- 验证技能功能

**触发方式**：创建或编辑技能时使用。

## 六、OpenSpec 技能

### 24. openspec-propose（提出变更）

**中文描述**：一步生成所有工件来提出新变更。当用户想要快速描述他们想要构建的内容并获得完整的提案（包含设计、规范和任务）以备实施时使用。

**用途场景**：
- 提出新功能变更
- 快速生成变更提案

**触发方式**：用户描述想要构建的内容时使用。

---

### 25. openspec-explore（探索模式）

**中文描述**：进入探索模式 - 用于在变更之前或期间探索想法、调查问题和澄清需求的思考伙伴。

**用途场景**：
- 探索变更想法
- 调查问题
- 澄清需求

**触发方式**：需要深入思考和探索时使用。

---

### 26. openspec-apply-change（应用变更）

**中文描述**：实现 OpenSpec 变更中的任务。当用户想要开始实现、继续实现或处理任务时使用。

**用途场景**：
- 开始实现变更
- 继续实现变更
- 处理变更任务

**触发方式**：用户要求实现变更时使用。

---

### 27. openspec-sync-specs（同步规范）

**中文描述**：将变更的增量规范同步到主规范。当用户想要更新主规范以包含来自增量规范的变更，而不归档变更时使用。

**用途场景**：
- 同步增量规范到主规范
- 更新规范文档

**触发方式**：需要同步规范时使用。

---

### 28. openspec-archive-change（归档变更）

**中文描述**：在实验工作流中归档已完成的变更。当用户想要在实现完成后完成并归档变更时使用。

**用途场景**：
- 归档已完成的变更
- 结束实验工作流

**触发方式**：变更实现完成后使用。

---

### 29. openspec-superpowers-workflow（OpenSpec+Superpowers 混合流程）

**中文描述**：当开始一个新的开发变更时使用，结合 OpenSpec 的结构化规划和 Superpowers 的质量保证技能，形成一套完整的开发流程。

**用途场景**：
- 新功能开发的完整流程
- 架构重构项目
- 需要系统化分析的复杂 Bug 修复

**触发方式**：开始新的开发变更时使用。

**流程阶段**：
- **Phase 1（规划）**：openspec-propose → brainstorming → openspec-explore
- **Phase 2（实施）**：writing-plans → test-driven-development → systematic-debugging → verification-before-completion
- **Phase 3（归档）**：人验证 → openspec-archive-change

**触发方式**：开始新的开发变更时使用。
