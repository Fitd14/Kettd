# Bench — PaperTodo（桌面便签）× Kettd 便签重设计

- 生成：2026-09-04 · 目的：**找借鉴** · 维度：交互模式 / 视觉语言 / 内容·IA · 预算：快拆
- 竞品定位：PaperTodo = 极简 Windows 桌面便签（WPF 原生，"让桌面上有几张安静、不打扰人的纸"），**与 Kettd 便签高度同品类**（direct competitor）。
- 依据：GitHub README + 公开介绍（未做登录后交互级体验，结论基于公开信息）。

## 竞品能力盘点（核实过）
- **关联/双向绑定**：README 未描述"完整双向同步"，实为 **跨纸片拖「关联图标」+ 拖文件/文件夹到待办项**（关联 = 快捷方式/指针，非图状双链）。
- **背景/主题**：跟随系统 / 浅色 / 深色；内置 **暖纸·墨·林·霞 四套配色**；支持自定义字体（放 `papertodo.ttf`）。
- **设置/交互**：失焦自动收起为**胶囊**、停靠屏幕边缘、hover 预览；一键置底 + 鼠标穿透；笔记字号 Ctrl+滚轮；待办拖拽排序 / 多行粘贴；每张纸独立窗口；多显示器换边；**可拖拽绑定至任意第三方软件窗口**。

## Castle vs Shack
- 🏰 Castle（绕开）：绑定第三方窗口 / 多屏换边依赖 WPF 原生窗口钩子，工程量大；"关联万物 + 脚本胶囊"是长期生态沉淀。
- 🏚️ Shack（可学）：预设纸色主题、失焦折叠胶囊、拖拽排序、跟随系统主题——表层可模仿。
- ⚠️ 冰山一角提醒：看到的是它 ship 的功能，背后的研究/取舍未知，别因"它做了"就以为适合我们。

## 逐条 3 问校验（针对你问的三点 + 我额外发现的高契合交互）

### A. 双向绑定文档 → 不照搬，降级为「轻量关联」
- 为什么 work：便签是临时纸片，关联=快捷方式，把散落任务与笔记/文件串起来，减少上下文切换。
- 上下文匹配：**partial**。Kettd 数据模型已有 `Task.note` + `notes[]`（任务自带笔记）；但"跨便签/图状双向链接 + 关联外部文件"会新增关系边 + 文件路径，把 Kettd 推向 Notion-like，**违背"轻量记录+汇总、反功能广度"定位**（PRD anti-metric）。
- 副作用：数据模型复杂化、迁移风险、UI 变重、破坏"3 秒记"。
- **结论**：❌ 不做完整双向绑定。✅ 可选轻量：给 Task 加一个**单向 `link`（URL/文件路径）字段**，便签/详情里"打开"即可。优先级低。

### B. 自定义背景色 → 借鉴（改造为预设，非取色器）
- 为什么 work：便签是常驻桌面物件，"选一张合眼缘的纸"强代入感、低成本。
- 上下文匹配：**yes**。Kettd 已有 HSL token + theme + 暗色；便签本就要融入桌面，给几套**预设纸色**极自然（与我们刚定的"暖白纸"同源）。
- 副作用：小，只要**预设而非自由取色**，避免"设置爆炸"。自定义字体对 n=1 价值低，缓。
- **结论**：✅ 借鉴。便签提供 **3–4 套预设纸色**（暖白纸 / 牛皮纸 / 淡青 / 暗墨），走 token。中优先。

### C. 多样化设置 → 不追求"多"（会背叛定位）
- 上下文匹配：**partial/no**。Kettd 明确"少即是多"、PRD 把"功能广度"列为反指标。堆设置项 = 认知负担 + 与"安静文具"心智冲突。
- **结论**：❌ 不为"多样化"而多样化。只从 PaperTodo 里挑 **2–3 个高价值、低复杂度**的交互单独借鉴（见 D/E）。

### D. 失焦折叠成「边缘胶囊」+ hover 预览 → 值得对比，但谨慎
- 为什么 work：极致不打扰，比"降低透明度"更省桌面空间。
- 上下文匹配：**yes（目标一致）**，但**副作用中**——我们刚把三形态收敛成单一便签，再加"折叠态"有重蹈多形态覆辙的风险。
- **结论**：⚠️ 改造借鉴。可作为"移出淡化"的**替代/进阶选项**（二选一，别同时上），先不做，观察淡化态够不够。

### E. 待办拖拽排序 → 借鉴（行业标配）
- 为什么 work：便签/今日清单顺序承载优先级，键盘/鼠标重排是基本预期。
- 上下文匹配：**yes**，成本低。
- **结论**：✅ match/borrow。便签与今日清单支持拖拽排序。

### F. 鼠标穿透 / 一键置底 / 绑定第三方窗口 → 回避或延后
- 鼠标穿透与"移出仍可扫读、移入可操作"冲突；置底/绑定第三方窗口 = WPF 深钩子，Castle 级工程量，短期不碰。
- **结论**：❌ avoid/defer。

## 视觉策略决策
- **对品类 lean-in、对具体视觉 diverge**：认同 PaperTodo 的"安静纸片"品类语言（无边框纸、置顶/置底、失焦不打扰），但**具体视觉走现代极简暖白**（我们已把复古收向现代），刻意不撞它的拟物暖黄。

## Takeaways 汇总
- borrow：预设纸色主题（B）、拖拽排序（E）
- match：跟随系统浅/深主题（已有，钉牢）
- 改造/观察：边缘胶囊折叠（D，先不上）
- avoid：完整双向绑定（A，改单向 link）、多样化设置堆叠（C）、鼠标穿透/置底/绑定第三方窗（F）

## 对便签规格的建议增量（待你点头再改 spec）

2. 待办清单**拖拽排序**（便签 + 今日视图）。
3. （可选，低优先）Task 加**单向 `link`** 字段替代"双向绑定"。
4. 不引入：图状双链、自由取色器、鼠标穿透/置底/绑窗。
