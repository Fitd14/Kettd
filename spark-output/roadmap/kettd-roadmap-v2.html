北极星：桌面上的「个人知识 · 待办网」

待办与知识是一张互链的网，桌面便签是你主动贴到手边的那一小撮。产品内核从「待办 app + 可选便签」→「待办 + 知识 双主体，便签是统一界面层」；知识库（KB）从"暂缓插件"转正为核心地基。

不变红线：离线 · 不出网 · 数据只在本机 · 反功能广度（不做平台/第三方组件、不做 Obsidian 式双链插件生态）。KB 定位 = "待办的上下文资料"，不是"第二大脑工程"。

四个地平线

H0 · Now（1–2 周）
兑现 v2.1 承诺
  • 毛玻璃真机验收 + push 回滚点
  • 埋点前端尾巴 + D5 定版
  • 便签 v2.1 版：单张 · 固定/拖拽记位/移出淡化/纸色
出口：v2.1 正式发布
H1 · Next（3–5 周）
React 地基 + 便签网雏形
  • v3 迁移 M1–M5（含五视图重设计落地）
  • 多张便签：待办 + 自由；收纳/淡出机制
  • KB 最小地基：片段 + 搜索（不做双链）
🚦 验证门：多张便签 & "钉" 到底用不用 → 决定是否重投 KB
H2 · Later（1–2 月）
知识网成型
  • 知识便签：钉 KB 片段到桌面
  • 任务 ↔ 知识 单向 link（验证后评估活引用）
  • KB 编辑/组织体验成熟化
🚦 压在 H1 验证之后 · 命门：会不会"壁纸化"
H3 · Horizon（不承诺）
探索
  • 回顾页数据洞察（热力图/时间轴已有雏形）
  • 活引用 / 跨便签关系可视化
  • 可选外接 Obsidian（当桥不当核心）

排序逻辑（为什么这个顺序）

1 先兑现信任是资产，追新前先结 v2.1 承诺。
2 再换地基React 是所有新 UI 的载体，先迁避免在 vanilla 做要扔的活。
3 低成本探针多张便签 + 钉，先证"钉到桌面"是不是真需求。
4 验证后才重投KB 压在验证之后——最贵的错误是自嗨建库。

关键假设（每条标最便宜的验证）

假设风险最便宜验证
用户会把资料钉桌面常驻（非壁纸化）ValueH1 自由便签先上，看"钉了还看不看/多久清"
待办需要挂上下文资料Value先做任务单向 link，看使用率
多张便签比单张有用Usability/ValueH1 直接给多张，观察创建数
React 迁移不拖垮 v2.x 迭代FeasibilityM1 capture 试点先跑通
单人离线工具靠"工作台化"提粘性留存埋点(已实现)看 4 周留存与功能触达

对已产出物的影响

五视图 UI 设计增量（已定稿）→ 归入 H1 的 M3 落地。便签规格拆两半：H0（Rust+CSS 单张）+ H1（多张/多类型）。知识库可行性 → 从"暂缓"升级为 H2 核心，但投入时机受 H1 验证门约束。回顾页热力图/时间轴 → H1 迁移时落地，数据洞察深化留 H3。

一句话：近期先兑现、中期换地基并验证"钉"的行为、远期才把知识网做实——用最小成本先证明愿景成立，再重投。
