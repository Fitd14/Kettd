# Scope — Kettd · kb 知识库（H2 转正设计）

- **生成时间**：2026-09-09
- **需求来源**：`spark-output/frame/kettd-knowledge-base-feasibility.md`（09-04 可行性，暂缓）＋ `spark-output/roadmap/kettd-roadmap-v2.md`（KB 转正核心地基，H2）＋ `src-tauri/docs/ARCHITECTURE-v3.md` §扩展点（KbItem ACL）＋ `spark-output/context/frame.json`

## 产品定位

Kettd：离线、数据在本机的个人待办工具；愿景「待办 + 知识 双主体，便签是统一界面层」。**kb = 「待办的上下文资料」层**，不是第二大脑工程。owner 定位纠偏（09-04）：不做 Obsidian 竞品，做「个人化、可自定义」——知识库是让小柯把工作台捏成自己想要的样子的一项能力。

## 目标

**业务目标**：
- 「记待办」→「我的工作台」提粘性（NSM=4 周留存）
- 占住差异化空位：待办为主 · 知识为辅 · 离线轻量（竞品扫描：无人做此组合）

**产品目标**：
- 做某条待办时就地调出背景资料/链接（机会 1：重要性 H × 满足 L）
- 记任务时顺手存链接/片段、之后能搜回来（机会 2：同上）
- 已完成任务连同资料沉淀成可检索记录（机会 4：中）

## 目标用户

- 小柯（n=1 persona，owner 本人）：待办在 Kettd、知识散在别处，做事时来回切、复制粘贴上下文。

## 功能清单（原需求文档里的）

| 功能 | 描述 | 优先级 | 文档显式 |
| --- | --- | --- | --- |

## 约束

- 红线：离线 / 不出网 / 数据只在本机 / 反功能广度
- 技术：Tauri v1 + React 新栈；**不加 ORM/SQLite/tantivy**（升级触发：条目 >5k 或搜索 P95 >200ms）
- 架构：KbItem 与 Task **ACL 解耦**（`KbRef(id)`）——命门假设失败时 KB 可整体降级不伤 Task 聚合
- 交互：不破坏「3 秒记」捕获核心
- 时机：原计划压 H1 验证门后；**但钉动作已被便签分离退役（判据失效），且 owner 主动要求设计 KB 本身即需求信号**

## 不做什么

第二大脑工程 / 双链插件生态 / 云同步多端账号 / AI 语义检索。

## 设计 implications

1. KB 进主窗侧栏第六视图（设置之前），不新开窗口
2. 搜索是第一交互（两个高优机会都是「查回来」）：搜索框置顶、键入即过滤、命中高亮
3. 任务↔资料入口长在任务详情/行上（就地可达）；KB 反向列表次要
4. 新增入口全部过「3 秒记不变重」审查
5. 视觉沿用纸感令牌 + 卡片家族语言（KB 条目=纸片隐喻）
