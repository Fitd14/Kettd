# 设计增量 · 收件箱 UI 优化（理念不变 · 处理漏斗）

- 状态：定稿待实现（UI 层，不改捕获缓冲理念）· 2026-09-04 · 供 M3
- 关联：`review-redesign-spec.md`、`sticky-note-component-spec.md`（拖拽排序共用）、`inbox_wireframe.png`
- 现状锚点：`inboxList = live().filter(t=>!done && !plannedDate && !dueAt)`（`index.html:225`）；`viewInbox`/`rowEl`/`newBar`。

## 0. 一句话
把收件箱从"静态清单 + 每行常驻按钮"升级为**清空工作台**：列表回归"读"，处理动作按需出现，用**老化**而非截止来制造温和压力，支持**批量**与**拖拽**清空。

## 1. 五项优化（对应骨架图 ①–⑤）

### ① 处理动作收进 hover（P1）
- 默认行只保留：勾选框 · 标题 · 分类 chip。**移除每行常驻的「加入今天」按钮**。
- hover / 键盘聚焦某行 → 行尾浮出紧凑动作：`→今天` `排期…` `⋯`(详情/删除)。
- 触屏/无 hover 环境：点行展开详情（现有 `detailEl`）承载动作，不依赖 hover。

### ② due 列 → 老化（P1）
- 收件箱条目本就无 dueAt/plannedDate，删掉右侧恒为「—」的截止列，宽度还给标题。
- 改暴露**滞留时长**：`今天 − createdAt(日)`。分组与老化色见 ③。

### ③ 老化分组 + 批量处理栏（P1）
- 列表按滞留分三组：**今天进的 / 本周 / 更早（≥5 天）**；组标题显条数。
- 「更早」行左侧一条**琥珀色竖条 +「滞留 N 天」badge**（`--pri-med` 系），**不用红色**（避免焦虑，守"安静文具"调性）。
- 顶部**批量处理栏**：勾选任意行后浮现「已选 N · 加入今天 / 排期… / 删除」；未勾选时不占位。
- 数据：批量 = 逐条 `updateTask`（plannedDate / 删除走软删）；建议加 `reorder/updateTask` 之外的**批量命令** `update_tasks(ids, patch)` 减少往返（可选优化）。

### ④ 拖到右侧「今天」= 加入今天（P3，与便签/今日拖拽共用）
- 内容区右侧一个常驻「今天」drop 目标（或拖到侧栏「今天」导航项）。
- 拖入 → `updateTask(id,{plannedDate: today()})`，行从收件箱消失、进今天。
- 与 §12.2 便签/今日的 `sort_order` 拖拽同一套交互库，统一实现。

### ⑤ 计数去重 + 空态正反馈（P2）
- 标题「收件箱 · N 条未整理」保留一处，删掉正文重复的「还没安排的事 · N」。
- 空态从"想到什么就快速记录"升级为**成就感**：收件箱清空时显示「都安排好了 ✓」（呼应移出变淡/安静的正情绪）。

## 2. 弱化项（P2）
- 优先级灰点：刚捕获多为默认 med，收件箱里信息量低 → **只对手动设过的显**优先级点；分类 chip 保留。

## 3. 交互态与数据
- 全部基于现有字段，**无新增数据模型**（老化用 `created_at` 派生；加入今天用 `plannedDate`）。
- 唯一可选后端增量：`update_tasks(ids,patch)` 批量命令（性能优化，非必需）。
- 三终态：成功（条目移出/入今天，轻 toast）；失败（`savefail` 重试，沿用现有）；空（正反馈态）。

## 4. 可访问性
- hover 动作必须有键盘等价（聚焦行显动作 / 快捷键 `T` 加入今天、`E` 排期、`X` 删除、`Enter` 展开）。
- 老化色非唯一信息载体（"滞留 N 天"有文字）；琥珀与背景对比 ≥3:1。
- 拖拽有非拖拽替代（批量栏 / 行内动作），不锁死键盘/触屏用户。

## 5. 验收（Given/When/Then）
- AC1 默认行无常驻按钮，hover/聚焦才出处理动作。
- AC2 收件箱不显示空的截止列；显示老化分组与"滞留 N 天"。
- AC3 勾选多行 → 顶部批量栏浮现，可一次加入今天/排期/删除。
- AC4 拖条目到「今天」= 加入今天并即时移出收件箱。
- AC5 计数只出现一次；清空后显示"都安排好了 ✓"。

## 6. 工时（M3 估）
- 行/hover/分组/老化色 + 批量栏（前端）~2h
- 拖到「今天」drop（复用拖拽库）~1h
- 空态/计数/优先级弱化 ~0.5h
- 可选 `update_tasks` 批量命令（后端）~1h
合计 ~3.5–4.5h。
