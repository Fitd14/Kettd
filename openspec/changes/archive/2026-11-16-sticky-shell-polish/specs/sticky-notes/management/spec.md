# Spec Delta

## Purpose

让用户在一个独立页面里以卡片形式浏览、搜索、打开、新建与删除全部便签，使便签从「设置页里的一行文字」变成可扫读、可操作的管理面。

## ADDED Requirements

### Requirement: 便签页入口与路由

系统 SHALL 在主导航侧栏提供「便签」入口；用户激活后 MUST 进入 `#/sticky` 路由并渲染便签卡片页。便签页 MUST 作为一级视图复用统一视图骨架（`.view` 的 padding / gap / 滚动约定），MUST 支持以 `#/sticky` 深链启动或刷新直达，且 MUST NOT 回落「今天」视图。侧栏折叠态下入口 MUST 仍可点击（仅图标 + tooltip）。

#### Scenario: 从侧栏进入便签页

- **WHEN** 用户点击侧栏「便签」
- **THEN** 地址 hash 变为 `#/sticky`，主区域渲染便签卡片页，侧栏对应项显示选中态

#### Scenario: 深链直接打开便签页

- **WHEN** 应用以 `#/sticky` 启动，或在便签页刷新
- **THEN** 直接进入便签卡片页，不回落「今天」

#### Scenario: 侧栏折叠

- **WHEN** 侧栏处于折叠态
- **THEN** 便签入口仍可点击并进入 `#/sticky`，不新增另一套导航

### Requirement: 便签卡片内容

每张便签 MUST 渲染为一张卡片，展示：正文纯文本摘要（剥离 Markdown 语法，取约 120 字，超出省略）、更新时间、可见或隐藏状态，以及知识来源标记（若有）。正文为空时 MUST 显示占位文案。卡片 MUST NOT 内嵌可编辑富文本编辑器。

#### Scenario: 自由便签卡片

- **WHEN** 便签没有知识来源且正文包含 Markdown 语法
- **THEN** 卡片摘要显示剥离 Markdown 后的纯文本，最多约 120 字，超出以省略号截断

#### Scenario: 知识便签卡片

- **WHEN** 便签的 `kbRef` 指向存在的知识条目
- **THEN** 卡片显示关联知识条目标题与「知识来源」标记

#### Scenario: 关联知识条目已删除

- **WHEN** 便签的 `kbRef` 指向已不存在的知识条目
- **THEN** 卡片显示「知识条目已删除」类失效提示，页面不崩溃、不整树卸载

#### Scenario: 空正文

- **WHEN** 便签正文为空
- **THEN** 卡片显示「（空）」类占位文案，仍可打开与删除

### Requirement: 卡片操作与可见上限

卡片 MUST 提供「打开」与「删除」操作，页面 MUST 提供「新建便签」。打开 MUST 复用既有便签打开语义：已可见便签聚焦其窗口，隐藏便签受可见合计上限约束；达到上限时 MUST 显示中文提示「便签最多同时打开 5 张，请先关闭一张」且不改变便签状态。删除 MUST 为两步确认：首次触发进入确认态，确认后删除并移除卡片，取消则保留。

#### Scenario: 打开隐藏便签

- **WHEN** 可见便签少于 5 张且用户点击某隐藏便签的「打开」
- **THEN** 该便签变为可见，便签窗口出现，卡片状态与计数更新

#### Scenario: 打开时超过可见上限

- **WHEN** 可见便签已达 5 张且用户点击某隐藏便签的「打开」
- **THEN** 显示上限中文提示，便签保持隐藏，卡片与计数不变

#### Scenario: 两步确认删除

- **WHEN** 用户点击卡片「删除」进入确认态，随后点击「确认删除」
- **THEN** 便签数据与便签窗口被删除，卡片从列表消失

#### Scenario: 取消删除

- **WHEN** 用户在确认态点击「取消」或离开确认态
- **THEN** 便签保留，卡片仍在列表中

#### Scenario: 新建便签成功

- **WHEN** 用户点击「新建便签」且可见便签少于 5 张
- **THEN** 创建一张可见的自由便签，卡片出现在列表中

#### Scenario: 新建便签超过可见上限

- **WHEN** 可见便签已达 5 张且用户点击「新建便签」
- **THEN** 显示上限中文提示，不创建新便签

### Requirement: 搜索过滤

页面 MUST 提供搜索输入框，输入时 MUST 对便签正文纯文本与关联知识条目标题做大小写不敏感过滤。无匹配时 MUST 展示空结果提示；清空搜索 SHALL 立即恢复全部卡片，且过滤 MUST 在本地完成、不触发后端请求。

#### Scenario: 命中正文

- **WHEN** 用户输入某个便签正文中存在的词
- **THEN** 列表只保留命中的卡片，其余卡片隐藏

#### Scenario: 命中知识标题

- **WHEN** 用户输入某个知识条目标题中的词
- **THEN** 引用该知识条目的便签卡片保留

#### Scenario: 无匹配结果

- **WHEN** 搜索词不匹配任何便签正文或知识标题
- **THEN** 展示「没有匹配的便签」类空结果提示

#### Scenario: 清空搜索

- **WHEN** 用户清空搜索框
- **THEN** 全部卡片恢复显示

### Requirement: 空态与计数

便签总数为 0 时 MUST 展示空态，说明便签用途并引导新建。页面 MUST 展示可见 / 隐藏计数与可见上限（5），计数 MUST 与后端便签列表一致。

#### Scenario: 没有任何便签

- **WHEN** 用户进入便签页且便签列表为空
- **THEN** 展示空态文案与「新建便签」按钮

#### Scenario: 计数展示

- **WHEN** 存在 3 张可见、2 张隐藏便签
- **THEN** 页面显示「可见 3/5 · 隐藏 2」类计数

### Requirement: 数据实时同步

便签页 MUST 订阅 `store-changed` 事件并在便签数据变化时刷新列表。便签窗口内的编辑、隐藏与删除 MUST 在不手动刷新页面的情况下反映到卡片与计数。

#### Scenario: 便签窗口编辑后摘要更新

- **WHEN** 用户在便签窗内编辑正文并保存
- **THEN** 便签页收到 `store-changed` 后重新拉取列表，卡片摘要更新

#### Scenario: 便签窗口关闭后状态更新

- **WHEN** 用户关闭（隐藏）一张便签窗口
- **THEN** 卡片显示隐藏状态，可见 / 隐藏计数更新

### Requirement: 与设置页的关系

设置页便签区 MUST 提供进入便签页的入口；便签页 SHALL 是便签浏览与删除的主入口，设置页 MUST 至少保留外观设置（纸面、花纹、移出淡化）而不成为唯一管理入口。

#### Scenario: 从设置页进入便签页

- **WHEN** 用户在设置页便签区点击「管理便签」类入口
- **THEN** 跳转到 `#/sticky` 并渲染便签卡片页

#### Scenario: 设置页保留外观设置

- **WHEN** 用户打开设置页便签区
- **THEN** 纸面、花纹、移出淡化设置仍可操作，且不影响便签页的浏览入口
