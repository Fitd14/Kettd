# Spec Delta

## Purpose

定义托盘菜单的最终可点项集合、勾选态与保留项行为，确保精简后的托盘只保留高频入口，且被移除项不造成功能入口丢失。

## ADDED Requirements

### Requirement: 托盘菜单项集合

托盘菜单 MUST 只包含以下五个可点项：「打开主界面」「待办悬浮窗」「新建便签」「打开数据文件夹」「退出」，并以分隔线与勾选项组织。「显示全部便签」「隐藏全部便签」「快速记录」「本周汇总导出」「管理提醒」MUST NOT 再出现在托盘菜单中。

#### Scenario: 打开托盘菜单

- **WHEN** 用户打开托盘图标菜单
- **THEN** 菜单只显示五个可点项与必要分隔线，不显示已移除的五项

#### Scenario: 已移除项不再出现

- **WHEN** 用户检查托盘菜单的任意层级
- **THEN** 找不到「显示全部便签」「隐藏全部便签」「快速记录」「本周汇总导出」「管理提醒」

### Requirement: 待办悬浮窗勾选态

「待办悬浮窗」菜单项 MUST 反映待办悬浮窗当前是否可见：可见时显示勾选，不可见时不显示勾选。点击该项 SHALL 切换悬浮窗显示 / 隐藏，并立即同步勾选态；应用启动时 MUST 按持久化的悬浮窗可见状态初始化勾选态。

#### Scenario: 启动时同步

- **WHEN** 应用启动且待办悬浮窗按持久化状态可见
- **THEN** 托盘菜单的「待办悬浮窗」项显示勾选

#### Scenario: 点击切换

- **WHEN** 用户点击「待办悬浮窗」
- **THEN** 悬浮窗按当前状态显示或隐藏，勾选态随新状态更新

### Requirement: 保留项行为

「打开主界面」SHALL 显示并聚焦主窗口；「新建便签」SHALL 走与全局新建便签热键相同的创建入口；「打开数据文件夹」SHALL 打开当前数据目录；「退出」SHALL 走应用正常退出流程。以上行为 MUST 与精简前一致。

#### Scenario: 打开主界面

- **WHEN** 用户点击「打开主界面」且主窗口已隐藏
- **THEN** 主窗口显示并获得焦点

#### Scenario: 新建便签

- **WHEN** 用户点击「新建便签」
- **THEN** 新建一张便签，效果与全局新建便签热键一致

#### Scenario: 打开数据文件夹

- **WHEN** 用户点击「打开数据文件夹」
- **THEN** 系统文件管理器打开当前数据目录（`KETTD_DATA_DIR` 覆盖时也生效）

#### Scenario: 退出

- **WHEN** 用户点击「退出」
- **THEN** 应用按既有退出流程结束，不残留托盘图标

### Requirement: 移除项不丢失功能入口

被移除的五个托盘项对应的能力 MUST 仍可通过其它入口使用：快速记录可经全局热键与设置页热键配置入口触发，提醒管理可在主导航「计划」视图中使用，周汇总导出可在主导航「回顾」视图中使用，便签显隐可在便签管理页与便签窗口中操作。

#### Scenario: 快速记录仍有入口

- **WHEN** 用户按全局快速记录热键
- **THEN** 快速记录条呼出并可回车入库

#### Scenario: 提醒管理仍有入口

- **WHEN** 用户进入「计划」视图
- **THEN** 提醒列表与管理操作可用

#### Scenario: 周汇总导出仍有入口

- **WHEN** 用户进入「回顾」视图
- **THEN** 周汇总与导出操作可用

#### Scenario: 便签显隐仍有入口

- **WHEN** 用户需要重新显示或隐藏便签
- **THEN** 可在便签管理页或便签窗口内完成，不依赖托盘菜单

### Requirement: 菜单与文档一致

`docs/ARCHITECTURE.md` 的托盘菜单段落 MUST 与实现的可点项集合一致；文档 MUST NOT 继续列出已移除的五项作为托盘入口。

#### Scenario: 文档核对

- **WHEN** 开发者对照 `docs/ARCHITECTURE.md` §5 托盘段落与实现
- **THEN** 两者列出的菜单项集合一致，且不包含已移除项
