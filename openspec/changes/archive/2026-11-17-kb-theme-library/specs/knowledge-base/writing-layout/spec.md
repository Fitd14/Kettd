# Spec Delta

## MODIFIED Requirements

### Requirement: 不改变主题与字号层级

布局调整 MUST NOT 改变现有配色 token、界面 chrome 的四档字号与行高（正文 1.85、H1–H6 阶梯）；阅读面的字号、字距与列宽由用户档位决定，布局改动 MUST NOT 改动它们。反过来，阅读主题（见 `knowledge-base/reading-themes`）MAY 改变阅读区的配色、字族、行高、标题倍率与装饰几何（纸面圆角与投影、引用与代码块样式、表格线/斑马纹/圆角、链接与图片），但 MUST NOT 改变正文列宽与居中、左右留白下限、底部写作留白与滚动容器结构——这些仍归本能力。

#### Scenario: 深色主题视觉一致

- **WHEN** 在深色主题下切换列宽档位
- **THEN** 正文颜色、字号、行高与切换前一致，仅列宽与对齐发生变化

#### Scenario: 阅读档位不被布局覆盖

- **WHEN** 用户已把阅读字号设为 18px，随后切换列宽档位
- **THEN** 正文仍为 18px，标题倍率与行高关系不变

#### Scenario: 主题不改变列宽与留白

- **WHEN** 用户选中一个把纸面圆角设为 24px、代码块圆角设为 16px 的阅读主题
- **THEN** 正文列宽仍为 `min(可用宽, 用户所选上限)`，两侧留白与底部留白不变，表格与代码块溢出时仍在正文列内横向滚动

#### Scenario: 主题与布局改动互不越界

- **WHEN** 开发者在布局变更里调整列宽档位
- **THEN** 不得顺手改主题变量或字号档位；主题侧新增变量也必须落在 `knowledge-base/reading-themes` 的白名单内，不新增布局令牌
