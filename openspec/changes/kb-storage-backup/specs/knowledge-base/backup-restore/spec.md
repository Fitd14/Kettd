# Spec Delta

## Purpose

定义知识库与任务数据的「用户手动备份」能力：把当前数据整理成单个 `.kettdbackup` 文件导出，导入时先预览再按条目 id 与更新时间做增量合并，冲突另存副本、绝不删除本地数据，使备份成为用户可掌控、可迁移、可反复演练的通道。

## ADDED Requirements

### Requirement: 手动导出单文件备份

系统 MUST 提供用户主动触发的「导出备份」，把当前数据整理成单个 `.kettdbackup` 文件并返回其绝对路径；导出 MUST NOT 依赖后台自动轮转，MUST NOT 修改现有数据。

#### Scenario: 导出成功

- **WHEN** 用户点击「导出备份」
- **THEN** 数据目录 `backups/` 下生成 `kettd-backup-<YYYYMMDD-HHmmss>.kettdbackup`（时间戳为本地语义时间）
- **AND** 界面提示成功并提供「打开所在文件夹」入口
- **AND** 导出期间现有任务、提醒、知识库条目不被修改，也不触发写前轮转

#### Scenario: 备份内容完整

- **WHEN** 导出的备份文件被解析
- **THEN** 文件 MUST 为单个 JSON 对象，包含格式标识、格式版本、应用版本、导出时间（本地语义字符串，MUST NOT 使用 UTC `Z` 时间）、任务/提醒/设置/便签快照、知识库条目（含正文与文件夹）、以及被引用资源的 base64 与 SHA-256
- **AND** 被正文引用的每个资源 MUST 出现在备份中

#### Scenario: 局部缺失不导致整体失败

- **WHEN** 某条正文文件缺失或某资源读取失败
- **THEN** 导出 MUST 继续完成，缺失正文按空处理、缺失资源跳过并计入「跳过」统计
- **AND** 返回结果 MUST 告知用户存在跳过的内容

#### Scenario: 重复导出不覆盖

- **WHEN** 同一秒内连续导出两次
- **THEN** 两次导出的文件 MUST 各自独立存在，后一次 MUST 生成不冲突的文件名
- **AND** 旧备份文件 MUST NOT 被覆盖

### Requirement: 导入前 dry-run 预览

导入 MUST 分两步执行：先解析备份文件并返回预览结果，用户确认后才真正写入；预览阶段 MUST NOT 修改任何数据。

#### Scenario: 预览统计

- **WHEN** 用户选择备份文件后触发预览
- **THEN** 界面展示新增、更新、冲突、跳过、资源新增、资源复用等数量
- **AND** 展示冲突条目标题列表（至少前若干条）供用户判断
- **AND** 数据目录内任何文件的内容与修改时间 MUST 不因预览而变化

#### Scenario: 拒绝预览

- **WHEN** 用户在预览后取消导入
- **THEN** 不写入任何数据，应用数据保持导入前状态

#### Scenario: 无效备份文件

- **WHEN** 文件不是合法 JSON、缺少格式标识或格式版本不受支持
- **THEN** 系统返回中文错误提示，MUST NOT 修改任何数据

### Requirement: 按 id 与更新时间增量合并

导入 MUST 按条目 `id` 匹配本地与备份数据，依据 `updatedAt` 判断新旧：备份较新则更新、本地较新则跳过；`updatedAt` 相等时 MUST 比较内容指纹（知识条目用 `contentHash` 结合标题/标签/文件夹的规范化等价性，任务/提醒用规范化 JSON 等价性），相同则跳过、不同则判定为冲突。

#### Scenario: 备份较新则更新

- **WHEN** 某条目 id 在本地与备份中都存在，且备份 `updatedAt` 晚于本地
- **THEN** 本地条目被备份内容更新，正文/资源同步补齐
- **AND** 该条目计入「更新」数量

#### Scenario: 本地较新则跳过

- **WHEN** 本地 `updatedAt` 晚于备份
- **THEN** 本地条目保持原样，备份内容不被应用
- **AND** 该条目计入「跳过」数量

#### Scenario: 内容相同不重复写入

- **WHEN** `updatedAt` 相等且内容指纹一致
- **THEN** 不产生写入，计入「跳过」数量

### Requirement: 冲突保留本地并另存副本

同一 id 在本地与备份中各自被修改（内容指纹不同）时，系统 MUST 保留本地版本，并把备份版本另存为标题追加「（导入冲突）」的副本；副本 MUST 使用新 id，`folderId` 跟随本地条目，时间戳取导入时刻。

#### Scenario: 冲突生成副本

- **WHEN** 同一 id 的本地与备份内容都被修改且指纹不同
- **THEN** 本地条目标题内容保持原样
- **AND** 新增一条标题为「<原标题>（导入冲突）」的副本，正文为备份版本
- **AND** 副本出现在本地条目所在的文件夹下，并在预览中被计入「冲突」

#### Scenario: 提醒冲突不重复提醒

- **WHEN** 某条提醒在本地与备份中都被修改
- **THEN** 保留本地提醒并跳过备份版本，MUST NOT 生成会触发重复通知的提醒副本
- **AND** 该条计入「冲突」

### Requirement: 绝不删除本地数据

导入 MUST NOT 删除或隐藏备份中不存在的本地条目、文件夹与资源；备份中缺失的字段 MUST 保持本地值。

#### Scenario: 备份不含的本地条目

- **WHEN** 本地存在某条目而备份中完全没有该 id
- **THEN** 导入后该条目仍在原位置可见，正文与资源完整

#### Scenario: 备份为旧版本条目

- **WHEN** 备份条目的字段少于本地（如新增字段）
- **THEN** 合并后 MUST 保留本地字段值，不得因备份缺字段而重置

### Requirement: 导入范围与设置保护

增量合并 MUST 覆盖任务、提醒、知识库条目、文件夹与被引用资源；应用设置与便签 MUST NOT 被导入覆盖（以本地为准）。

#### Scenario: 导入不改设置

- **WHEN** 用户导入一个来自其他设备的备份
- **THEN** 主题、热键、数据目录、提醒上限等设置保持本机值
- **AND** 便签窗口内容与位置保持本机值

### Requirement: 安全应用与可回退

真正写入前系统 MUST 轮转现有 `data.json` 与 `notes.json` 备份（各保留 5 份），写入 MUST 原子化；导入过程失败 MUST 保证数据仍可恢复到导入前状态。

#### Scenario: 应用前留档

- **WHEN** 用户确认执行导入
- **THEN** 系统在写任何数据前轮转主数据与知识库索引备份
- **AND** 导入失败时用户可凭这些备份恢复到导入前状态

#### Scenario: 资源解码校验

- **WHEN** 备份中的资源 base64 解码后 SHA-256 与声明的哈希不一致
- **THEN** 该资源被跳过并计入失败/跳过数量
- **AND** 引用它的正文仍可导入，不因单张图片失败而中止整个导入

#### Scenario: 重复导入幂等

- **WHEN** 用户对同一备份文件连续导入两次
- **THEN** 第二次 MUST 全部计入「跳过」，不新增副本、不更新时间戳

### Requirement: 导入完成后刷新

导入成功 MUST 通知前端刷新数据；正在展示的知识库、任务列表与便签 MUST 在刷新后呈现合并结果。

#### Scenario: 合并后界面刷新

- **WHEN** 导入并写盘成功
- **THEN** 主窗与已打开的便签收到数据变更通知并重新加载
- **AND** 界面上能看到新增条目与「（导入冲突）」副本
