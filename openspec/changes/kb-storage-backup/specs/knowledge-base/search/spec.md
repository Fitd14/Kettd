# Spec Delta

## Purpose

定义全局知识库搜索的行为契约：搜索范围严格限定为文件名称与文件夹目录名称，提供可解释的排序，前端据此真正过滤列表并展示文件夹路径面包屑，标签筛选保持为与搜索相互独立的过滤条件。

## ADDED Requirements

### Requirement: 搜索范围只含文件名与文件夹名

知识库搜索 MUST 只匹配条目标题与条目所属的祖先文件夹名称；MUST NOT 匹配正文内容，MUST NOT 匹配标签。

#### Scenario: 正文命中不再返回

- **WHEN** 用户搜索一个只出现在某条正文里、不在任何标题或文件夹名中的关键词
- **THEN** 该条目 MUST NOT 出现在搜索结果中

#### Scenario: 标签命中不再返回

- **WHEN** 用户搜索一个只作为标签存在、不在标题与文件夹名中的关键词
- **THEN** 该条目 MUST NOT 出现在搜索结果中
- **AND** 用户仍可通过标签筛选单独过滤该标签

#### Scenario: 文件夹名命中

- **WHEN** 用户搜索的关键词命中某文件夹名
- **THEN** 该文件夹下的条目 MUST 出现在结果中
- **AND** 结果行 MUST 显示该文件夹的路径面包屑

### Requirement: 结果排序可解释

搜索结果 MUST 按匹配强度排序：标题完全匹配优先于标题前缀匹配，标题前缀匹配优先于标题包含匹配；文件夹名匹配权重 MUST 低于标题匹配；同分结果 MUST 按 `updatedAt` 倒序。

#### Scenario: 标题完全匹配置顶

- **WHEN** 关键词与一条标题完全相等，同时命中另一条标题的中间片段
- **THEN** 完全匹配的条目排在包含匹配之前

#### Scenario: 标题命中优先于文件夹名命中

- **WHEN** 关键词同时命中一条的标题与另一条所属文件夹名
- **THEN** 标题命中的条目排在文件夹名命中的条目之前
- **AND** 两者都在结果中可见

#### Scenario: 同分按更新时间

- **WHEN** 两条条目匹配强度相同
- **THEN** `updatedAt` 较新的条目排在前面

#### Scenario: 每条只出现一次

- **WHEN** 同一条目的标题与多个祖先文件夹名都命中关键词
- **THEN** 该条目在结果中 MUST 只出现一次

### Requirement: 查询归一与空查询

搜索 MUST 对查询做首尾空白裁剪并大小写不敏感；空查询 MUST 返回全部条目并按 `updatedAt` 倒序，作为浏览视图而非搜索态。

#### Scenario: 大小写与空白

- **WHEN** 用户输入前后带空格或大小写混合的关键词
- **THEN** 匹配结果与去空白、统一大小写后的查询一致

#### Scenario: 清空搜索框

- **WHEN** 用户清空搜索词
- **THEN** 列表恢复为全部条目（按更新时间倒序），不再处于搜索过滤态

### Requirement: 前端真正过滤并展示路径

前端 MUST 用搜索命中集合真正过滤知识库列表，MUST NOT 只把命中项排前而继续显示未命中项；每条结果行 MUST 展示条目所在文件夹的路径面包屑（未分类条目明确标识）。

#### Scenario: 无结果空状态

- **WHEN** 搜索没有命中任何条目
- **THEN** 列表显示「没有匹配的笔记」类空状态文案
- **AND** 不显示未命中的条目

#### Scenario: 路径面包屑

- **WHEN** 结果中的条目位于多层文件夹内
- **THEN** 该行 MUST 显示从根到直接父级的文件夹路径
- **AND** 未分类条目 MUST 明确显示为未分类，而非空白

### Requirement: 标签筛选与搜索相互独立

标签筛选 MUST 作为独立过滤条件保留，可与搜索叠加；标签 MUST NOT 参与搜索命中判定。

#### Scenario: 搜索叠加标签

- **WHEN** 用户同时输入搜索词并选中某标签
- **THEN** 结果 MUST 同时满足「标题或文件夹名命中」与「具备该标签」
- **AND** 清空搜索词后标签筛选仍然生效

#### Scenario: 仅标签筛选

- **WHEN** 用户只选中标签不输入搜索词
- **THEN** 列表按标签过滤，不受搜索范围限制

### Requirement: 搜索在容量上限内可用

在知识库达到 5000 条上限时，搜索 MUST 仍能在一次交互内返回结果，不出现明显卡顿或阻塞输入。

#### Scenario: 满载搜索

- **WHEN** 知识库接近 5000 条且用户连续键入
- **THEN** 输入框保持可用，结果在键入停止后及时更新
- **AND** 不因搜索而整库重读正文
