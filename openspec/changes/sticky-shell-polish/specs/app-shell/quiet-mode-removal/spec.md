# Spec Delta

## Purpose

定义移除免打扰能力后的行为：设置页不再提供免打扰配置，提醒在所有时段按既有规则触发，旧数据中的免打扰字段被安全忽略。

## ADDED Requirements

### Requirement: 设置页不再提供免打扰

设置页 MUST NOT 渲染免打扰开关或起止时间输入；「提醒」区块 MUST 只保留每小时上限等其它提醒设置。应用 MUST NOT 再向后端提交或回显 `dnd` 字段，前端类型中 MUST NOT 包含免打扰配置。

#### Scenario: 设置页提醒区块

- **WHEN** 用户打开设置页的「提醒」区块
- **THEN** 看不到免打扰开关与起止时间，仅看到每小时上限等其它设置

#### Scenario: 保存设置不携带免打扰

- **WHEN** 用户在设置页修改任意其它设置并保存
- **THEN** 提交的设置载荷不包含 `dnd` 字段

### Requirement: 提醒在所有时段照常触发

调度器 MUST NOT 再按时段抑制提醒：到点的提醒 SHALL 按既有通知、每小时上限、snooze 与错过处理规则交付，MUST NOT 被静默入账，也 MUST NOT 再产生「免打扰期间有 N 条提醒」的合并补发。

#### Scenario: 深夜到点提醒照常通知

- **WHEN** 一条提醒在 23:10 到点且应用正在运行
- **THEN** 系统通知按既有规则发出，而不是被静默吞掉

#### Scenario: 跨零点无合并批次

- **WHEN** 时间跨过原先的 23:00–07:30 时段边界
- **THEN** 不产生任何免打扰合并通知或补发批次

### Requirement: 旧数据兼容

旧 `data.json` 含 `settings.dnd` 字段时 MUST 正常加载，字段被忽略且不生效，MUST NOT 进入恢复页或报错。应用保存后该字段可自然消失，无需手动迁移脚本。便签、任务、提醒等其它数据 MUST 不受影响。

#### Scenario: 旧数据启动

- **WHEN** 数据文件含有旧的 `settings.dnd` 字段
- **THEN** 应用正常启动，提醒不再受该时段配置影响，其它数据完整

#### Scenario: 保存后字段消失

- **WHEN** 用户在含旧 `dnd` 字段的数据上触发一次保存
- **THEN** 保存后的数据文件不再包含该字段，且不产生额外迁移报告

### Requirement: 既有提醒规则不变

移除免打扰 MUST NOT 改变提醒的其它规则：每小时上限、snooze、超过 24 小时记错过、启动补发合并、`fired` 去重、单次提醒完成语义均 MUST 保持现有行为。

#### Scenario: 每小时上限仍生效

- **WHEN** 每小时上限为 1 且同一小时有两条提醒到点
- **THEN** 只发出第一条，第二条排队到下个窗口

#### Scenario: 启动补发仍合并

- **WHEN** 应用未运行期间错过两条提醒，启动后首次调度
- **THEN** 合并为一条「错过 N 条提醒」通知，不逐条轰炸

#### Scenario: snooze 仍生效

- **WHEN** 用户对某条提醒执行稍后提醒
- **THEN** 通知在 snooze 到期后按既有语义再次触发

### Requirement: 文档与遥测不再描述免打扰

项目文档与 `docs/capability/` 中 MUST NOT 继续把免打扰描述为现存功能；遥测 MUST NOT 再上报 `reason=dnd` 的错过事件。架构文档的提醒规则段落 MUST 同步为「无免打扰时段」。

#### Scenario: 文档检索

- **WHEN** 在 `docs/` 检索「免打扰」
- **THEN** 只在历史变更记录或明确的「已移除」说明中出现，不再作为现行功能描述

#### Scenario: 遥测样例

- **WHEN** 检查提醒相关遥测事件与单测样例
- **THEN** 不再出现 `reason=dnd` 的语义
