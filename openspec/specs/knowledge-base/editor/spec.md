# knowledge-base/editor Specification

## Purpose
定义知识库条目与知识便签共用的 Markdown 编辑器的可观察行为，包括输入反馈、格式命令、链接与图片插入、保存与外部回填，确保内容不会因保存链路而静默改变或丢失。

## Requirements

### Requirement: 保存过程不打断编辑
编辑器的自动保存与外部数据刷新 SHALL NOT 让知识库视图出现空态占位、整列表重排或覆盖用户正在输入的内容。

#### Scenario: 自动保存后列表保持稳定
- **WHEN** 用户在知识库条目编辑器中输入并停止输入达到自动保存防抖时间
- **THEN** 保存完成后知识库列表不出现「空空如也」等空态占位，列表滚动位置与选中项不变

#### Scenario: 保存回包不覆盖新输入
- **WHEN** 自动保存的请求返回时用户已经继续输入了更多内容
- **THEN** 编辑器保留用户的新输入，不回灌旧内容、不重置光标位置

### Requirement: 输入过程保持流畅
编辑器的每次击键 SHALL 只更新必要范围，不得重建扩展集合、触发整页或整列表重渲染；Markdown 序列化 SHALL 仅在防抖后的保存时机执行。

#### Scenario: 长文档连续输入
- **WHEN** 用户在接近 5000 字的知识条目中连续输入
- **THEN** 每次击键不触发扩展重建与全列表数据重拉，输入无可感知卡顿

### Requirement: Markdown 保存保真
编辑器保存 SHALL 保留用户 Markdown 的语义信息；只允许无语义变化的归一化，且归一化结果在再次保存时保持不变（幂等）。

#### Scenario: 表格对齐信息保留
- **WHEN** 文档包含带对齐标记（`:---`、`:---:`、`---:`）的表格并保存后重新打开
- **THEN** 表格的对齐信息仍然保留

#### Scenario: 图片不会整体丢失
- **WHEN** 文档包含 Markdown 图片语法并保存
- **THEN** 图片节点被保留且可再次编辑，不会在保存后消失

#### Scenario: 有损转换必须提示
- **WHEN** 保存链路无法无损表达某段内容（例如不支持的 HTML、嵌入语法）
- **THEN** 系统在保存前给出明确提示或保留原文，不得静默丢弃

### Requirement: 标题级别可分级设置
编辑器 SHALL 提供分级标题下拉（正文、H1–H4），并支持行首输入 `#` 到 `####` 加空格的输入式标题；编辑器与阅读态 SHALL 有对应字号样式。

#### Scenario: 使用标题下拉
- **WHEN** 用户点击工具栏标题控件
- **THEN** 出现「正文 / H1 / H2 / H3 / H4」下拉，选择后当前段落应用对应级别，控件高亮当前级别

#### Scenario: 输入式标题
- **WHEN** 用户在行首输入 `### `（或 H1/H2/H4 对应标记）
- **THEN** 该行转换为对应级别的标题，编辑态与阅读态都呈现对应字号

### Requirement: 截图可粘贴为图片（仅知识库条目）
知识库条目编辑器 SHALL 支持把剪贴板中的截图粘贴为图片节点，并在保存后仍可渲染与再次编辑；便签编辑器 MUST NOT 启用图片插入（便签保持 500 字上限）；插入前 SHOULD 压缩到可接受的体积上限并在超限时提示。

#### Scenario: 粘贴截图
- **WHEN** 用户把截图粘贴到编辑器
- **THEN** 图片经压缩后插入正文并立即可见，保存后重新打开仍能显示

#### Scenario: 体积超限
- **WHEN** 待插入图片压缩后仍超过体积上限
- **THEN** 系统提示体积过大并拒绝插入，不写入数据

### Requirement: 行内格式与链接

编辑器 SHALL 支持斜体、删除线等行内格式；链接 MUST 通过 `[@文本](url)` 文本语法创建与修改，MUST NOT 使用模态对话框、浏览器原生 prompt 或阻塞编辑的浮层。

#### Scenario: 斜体与删除线
- **WHEN** 用户对选区点击斜体或删除线
- **THEN** 选区应用对应行内格式，Markdown 输出为 `*文本*` / `~~文本~~`

#### Scenario: 语法创建链接
- **WHEN** 用户在正文键入或粘贴 `[@示例](https://example.com)`
- **THEN** 该段转为链接，屏幕上只见「示例」二字（不含 `@`），保存后 Markdown 为 `[示例](https://example.com)`

#### Scenario: 纯方括号不转换
- **WHEN** 用户输入 `[备注](待定)` 或写完 `[备注]` 后又接着写括号内容
- **THEN** 文本保持原样，不生成链接，`@` 是唯一触发转换的标记

#### Scenario: 保存前归一化
- **WHEN** 文档中仍残留未被转换的 `[@文本](url)` 语法文本
- **THEN** 保存时该段按链接归一化，落盘 Markdown MUST NOT 含 `[@`

#### Scenario: 内联输入条修改地址
- **WHEN** 用户点击一条已有链接
- **THEN** 链接正下方出现一条内联输入条并预填当前地址，Enter 确认、Esc 取消、清空后确认即移除链接且保留文字；输入条不遮挡正文、不锁焦点，点击条外即关闭

### Requirement: 链接在编辑区可辨

编辑器正文与阅读态中的链接 SHALL 与正文文字有明显颜色差异并带下划线；颜色 MUST 取自配色令牌，MUST NOT 使用裸色值。

#### Scenario: 编辑态链接可见
- **WHEN** 条目正文含一条链接并把光标移出链接
- **THEN** 链接文字呈现链接色与下划线，与周围正文可一眼区分（深浅两套主题均成立）

#### Scenario: 阅读态一致
- **WHEN** 同一条目切到阅读态或经 Markdown 渲染显示
- **THEN** 链接仍为同一种链接色与下划线，不因渲染通道不同而回退成正文色

### Requirement: 外链点击不外泄导航

编辑器中的链接 SHALL 只在 `Ctrl/⌘ + 点击` 时用系统默认浏览器打开；普通点击 MUST 只把光标落进链接，MUST NOT 导航、MUST NOT 在应用窗口内加载外部页面。仅 `http`、`https`、`mailto` 协议的地址 SHALL 被识别为链接。

#### Scenario: 普通点击不导航
- **WHEN** 用户不带修饰键点击正文中的链接
- **THEN** 光标进入链接文字，窗口不跳转、不打开新窗口

#### Scenario: Ctrl 点击外链
- **WHEN** 用户按住 `Ctrl`（macOS 为 `⌘`）点击链接
- **THEN** 该地址在系统默认浏览器中打开，应用窗口保持当前页面

#### Scenario: 危险协议不成为链接
- **WHEN** 文档中出现 `[@点我](javascript:alert(1))` 之类的非白名单协议
- **THEN** 该段不转换为可点击链接，也不会被交给系统浏览器

### Requirement: 斜杠菜单提供链接项

斜杠菜单 SHALL 包含「链接」项，选中后插入 `[@文本](url)` 模板并把选区落在占位文本上；知识库条目与知识便签的编辑器 MUST 都提供该项。

#### Scenario: 斜杠插入链接
- **WHEN** 用户在空行输入 `/` 并选择「链接」
- **THEN** 光标处出现 `[@文本](url)` 模板，占位文本处于选中态，直接键入即可替换；正文不出现任何弹窗

#### Scenario: 便签窗同样可用
- **WHEN** 在知识便签编辑器中输入 `/` 并选择「链接」
- **THEN** 行为与知识库条目一致，插入同样的模板

### Requirement: 表格网格选择器可外部关闭

表格网格选择器打开后 SHALL 在点击选择器与按钮之外、或按下 `Esc` 时关闭；关闭 MUST NOT 影响已插入的表格。

#### Scenario: 点击外部关闭
- **WHEN** 用户点开表格图标后把光标移到正文或工具栏其他按钮并点击
- **THEN** 网格选择器消失，编辑内容不变

#### Scenario: Esc 关闭
- **WHEN** 网格选择器打开时用户按 `Esc`
- **THEN** 选择器关闭，光标回到打开前的编辑位置

#### Scenario: 悬停预览保留
- **WHEN** 鼠标在网格上移动
- **THEN** 高亮预览随行列变化，面板不因鼠标短暂移出按钮而关闭

### Requirement: 文档标题在正文首行编辑

知识条目的标题 MUST 呈现为正文纸面上的第一行（`.kb-doc-title`，位于标签行之上、正文之前），随正文一起滚动；顶部工具条 MUST 只保留只读镜像，不得再提供可编辑的标题控件。标题仍 MUST 只存条目名一个字段，改名走与文件树、搜索一致的更新链路。

#### Scenario: 打开条目即可在纸面上看到标题

- **WHEN** 用户打开任意知识条目
- **THEN** 正文纸面首行显示该条目的标题（衬线、字号为正文的两倍）
- **AND** 顶部工具条左端只显示只读镜像（锁标记 + 标题 + `只读` 标签），长标题单行省略且不可聚焦

#### Scenario: 点进标题即全选

- **WHEN** 用户点击正文首行的标题
- **THEN** 整条标题被选中，直接输入即整体替换，不需要三击或手动拖选

#### Scenario: 回车落盘并进入正文

- **WHEN** 用户在标题中按下 `Enter`
- **THEN** 标题改名被提交，光标落到正文第一段，不插入换行

#### Scenario: 转义放弃本次改名

- **WHEN** 用户在标题编辑中按下 `Esc`
- **THEN** 标题恢复为改名前的文本，编辑结束，不写盘

#### Scenario: 空标题不落盘

- **WHEN** 用户把标题清空后失焦
- **THEN** 该条目的名字保持改名前的值，列表与树中不出现空名条目
- **AND** 仅当条目本来就没有名字时，纸面首行显示占位符「未命名文档」

#### Scenario: 外部改名同步到纸面

- **WHEN** 用户在文件树中重命名了当前打开的条目
- **THEN** 正文首行的标题与顶部只读镜像同时更新为新名字，不需要重新打开

### Requirement: 文档标题不进 Markdown 文档树

条目的 `bodyMd` MUST NOT 包含标题行；复制文档为 Markdown 时 MUST 在正文之前补一行 `# 标题`，使粘出去的内容是一篇完整文档。

#### Scenario: 正文 Markdown 不含标题

- **WHEN** 用户编辑并保存一篇有条目的文档
- **THEN** 落盘的 `bodyMd` 从正文第一段开始，不含 `# 标题`，正文里也不因此出现重复的一级标题

#### Scenario: 复制时补首行标题

- **WHEN** 用户点击工具条的「复制 Markdown」
- **THEN** 剪贴板内容以 `# 标题` 开头，其后空一行接正文
- **AND** 标题为空时只复制正文，不生成空的 `#`
