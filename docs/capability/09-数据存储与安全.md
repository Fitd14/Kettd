# 09 · 数据存储与安全

## 设计

**数据目录**：`%APPDATA%\todo-list`

| 文件 | 内容 | 策略 |
| --- | --- | --- |
| data.json | 任务/提醒/设置 | 写前轮转 5 份备份，tmp+rename 原子写 |
| data.json.bak-1~5 | 轮转备份（bak-1 最新） | 设置页可查可恢复 |
| notes.json | 知识库条目 | 原子写，与主数据物理隔离 |
| runtime.json | fired 键/窗口位置/迁移报告/悬浮窗显隐 | 高频写不轮转；损坏静默重建 |
| events.jsonl | 本地度量事件 | >1MB 轮转归档 |
| data.v1.json | v1 迁移原件 | 永不删除、永不覆盖 |
| data.pre-split.json | schema 拆分前留档 | 已存在不覆盖 |
| exports/ | 周汇总导出 | 默认导出目录 |

**恢复**：设置页选备份槽位恢复；恢复成功覆盖写**不轮转**、清撤销栈、解除损坏态；v1 备份先迁移再恢复。

**损坏隔离**：主数据解析失败 → 另存 `data.corrupt.<时间戳>`，进恢复页，**绝不渲染假空态**。知识库损坏 → 静默空库，不传染主数据。

**v1 迁移**：首次加载懒迁移十规则（字段重命名、非法时间置 null、legacy 不伪造完成时刻、「个人」→生活、逾期一次性粘今天、多时刻原样保留等），原件永久留档。

**单实例**：重复启动弹「Kettd 已在运行（托盘里找回它）」后退出。

**回收站**：软删保留 30 天，启动时物理清理超期项。

**撤销**：删除撤销 LIFO 栈上限 50（任务/子任务/备注三类）；栈空兜底恢复最近软删任务。

## 开发指南

| 层 | 入口 |
| --- | --- |
| 分层 | `ports/store_backend.rs`（trait） → `infra/fs_store.rs`（生产） / `test_double::InMemoryBackend`（测试） |
| 编排 | `store.rs`（加载/保存/迁移/备份） |
| 原子写 | `fs_store.rs` `write_data_at`（tmp+rename）；`rotate_backups` 5 份 |
| 迁移 | `store.rs` `migrate_v1`（十规则）+ `normalize_stickies_v3` + schema split |
| 测试 | `cargo test` 用 `InMemoryBackend` + `FixedClock`，**不碰真实磁盘** |

关键约束：
- 新增持久文件必须走 `StoreBackend` trait，禁止直接 `fs::write`（破坏测试替身）
- 写前轮转是用户数据最后防线，**不可跳过**
- 损坏通道：主数据进恢复页；runtime 静默重建；KB 静默空库——**绝不渲染假空态**
- v1 原件 `data.v1.json` 永不删除；schema 拆分留档 `data.pre-split.json` 已存在不覆盖
- 用户数据目录 `%APPDATA%\todo-list`，测试/脚本**禁止写入生产目录**
- 时间全链路本地语义字符串，零 UTC 换算（`models.rs` `DateTimeLocal`）
