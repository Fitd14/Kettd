# 09 · 数据存储与安全

## 设计

**数据目录**：`%APPDATA%\todo-list`

| 文件 | 内容 | 策略 |
| --- | --- | --- |
| data.json | 任务/提醒/设置 | 写前轮转 5 份备份，tmp+rename 原子写 |
| data.json.bak-1~5 | 轮转备份（bak-1 最新） | 设置页可查可恢复 |
| notes.json | 知识库**索引**（KbItemMeta 数组，不含正文） | 先正文后索引；每次覆盖写前轮转 5 份；原子写，与主数据物理隔离 |
| notes.json.bak-1~5 | 知识库索引轮转备份（bak-1 最新） | 设置 → 备份与恢复可查可回滚 |
| notes/<id>.md | 知识库**正文**（Markdown，每条一个文件；id 仅 `[A-Za-z0-9_-]`） | 单条 tmp+rename 原子写；先于索引落盘 |
| assets/<sha256>.<ext> | 知识库图片（按内容哈希命名去重） | 原子写；删除条目不清理资源 |
| notes.v1.json | 旧格式 notes.json（正文内联）迁移前存档 | 不存在才写；永不覆盖 |
| folders.json | 知识库文件夹树 | 原子写；不存在视为空表 |
| runtime.json | fired 键/窗口位置/迁移报告/悬浮窗显隐 | 高频写不轮转；损坏静默重建 |
| events.jsonl | 本地度量事件 | >1MB 轮转归档 |
| data.v1.json | v1 迁移原件 | 永不删除、永不覆盖 |
| data.pre-split.json | schema 拆分前留档 | 已存在不覆盖 |
| exports/ | 周汇总导出 | 默认导出目录 |
| backups/ | 手动备份包（`kettd-backup-<时间戳>.kettdbackup`，单文件 JSON） | 导出命令写入；不自动轮转 |

**恢复**：设置页选备份槽位恢复；恢复成功覆盖写**不轮转**、清撤销栈、解除损坏态；v1 备份先迁移再恢复。知识库同页可选 `notes.json.bak-1~5` 回滚（备份解析成功才覆盖，恢复前当前档先轮转进 `bak-1`）。

**手动备份格式（.kettdbackup，kb-storage-backup D3/D4）**：单个 JSON 文件写 `<数据目录>/backups/kettd-backup-<YYYYMMDD-HHmmss>.kettdbackup`，顶层 `format = "kettd-backup"`、`formatVersion = 1`，另有 `appVersion` / `exportedAt`（本地语义字符串）。结构：`data`（Task/Reminder/Settings/StickyNote 快照）+ `kb`（条目元信息与正文、文件夹树）+ `assets`（正文引用到的图片 base64，带 `sha256` / `ext`）。上限：文本 256 MB、单资源 5 MB、资源 5000 个、条目 20000 条；扩展名白名单 png / jpg / webp / gif；只导出正文实际引用的资源，缺失或读失败计 `skipped` 不阻断。导入 `dryRun` 只解析与预览、绝不写盘；apply 落盘顺序固定 **assets → 正文 → folders → 索引 → data.json**（runtime 不动），应用前轮转由 `save_folders` / `save_notes` / `save` 各完成一次；设置与便签不覆盖、本地独有绝不删，同一备份重复导入全部 Skip。

**损坏隔离**：主数据解析失败 → 另存 `data.corrupt.<时间戳>`，进恢复页，**绝不渲染假空态**。知识库（notes/folders）解析失败 → 可恢复错误态（引导至设置 → 备份与恢复），不传染主数据。

**知识库存储（索引 + 正文分文件）**：`notes.json` 只存元数据数组（id/title/tags/folderId/order/pinned/时间戳/contentHash），正文按 `notes/<id>.md` 分文件，图片落 `assets/<sha256>.<ext>`。单条写序固定为「先正文、后索引」（各自 tmp+rename 原子写）；索引 `contentHash = sha256(正文)`，加载时重算校验：不一致以正文为准并顺手修复索引（不判损坏），正文文件缺失按空串加载（条目不丢）。索引每次覆盖写前轮转 `notes.json.bak-1~5`；`folders.json` 原子写、不轮转。

**迁移触发条件**：加载时发现 `notes.json` 任一元素含 `bodyMd` / `body_md`（旧版正文内联）即触发一次性迁移——`notes.v1.json` 存档（不存在才写，永不覆盖）→ 轮转备份 → 逐条写正文 → 最后原子写新索引。迁移失败置 `KB_UPGRADE_FAILED`，用户看到「知识库升级失败，原数据已保留，请重启后重试」；旧文件原样保留，下次启动重试。

**回滚步骤**：回退旧版本前把 `notes.v1.json` 复制回 `notes.json`（或把 `notes.json.bak-1` 复制回 `notes.json`），再安装旧版本；`notes.v1.json` 永不覆盖，可反复回滚。

**图片资源访问**：正文只存相对引用 `assets/<sha256>.<ext>`；渲染时前端 `rendering/asset-url.ts` 用 `Bootstrap.assetsDir` + Tauri `convertFileSrc` 转可加载地址，`tauri.conf.json` 以 `protocol.asset` + 窄 `assetScope`（`$APPDATA/todo-list/assets/**`）放行。保存/迁移时内联 `data:image` 自动外置为 `assets/`（MIME 白名单 png/jpg/webp/gif、按 sha256 去重）；抽不动的保留内联不丢图。已知限制：`KETTD_DATA_DIR` 自定义目录不在 assetScope 内 → 图片不显示（数据不丢）。

**v1 迁移**：首次加载懒迁移十规则（字段重命名、非法时间置 null、legacy 不伪造完成时刻、「个人」→生活、逾期一次性粘今天、多时刻原样保留等），原件永久留档。

**单实例**：重复启动弹「Kettd 已在运行（托盘里找回它）」后退出。

**回收站**：软删保留 30 天，启动时物理清理超期项。

**撤销**：删除撤销 LIFO 栈上限 50（任务/子任务/备注三类）；栈空兜底恢复最近软删任务。

## 开发指南

| 层 | 入口 |
| --- | --- |
| 分层 | `ports/store_backend.rs`（trait） → `infra/fs_store.rs`（生产） / `test_double::InMemoryBackend`（测试） |
| 编排 | `store.rs`（加载/保存/迁移/备份） |
| 手动备份 | `backup.rs`（格式/解析/合并计划纯函数）→ `store.rs` `export_backup_to_file` / `import_backup_from_payload` → `commands.rs` `export_backup` / `import_backup` |
| 知识库 | `store_notes.rs`（索引/正文/迁移纯函数）→ `store.rs` `reload_kb_items` / `save_notes` / `migrate_notes_legacy` |
| 原子写 | `fs_store.rs` `write_data_at`（tmp+rename）；`rotate_backups` / `rotate_notes_backups` 各 5 份 |
| 迁移 | `store.rs` `migrate_v1`（十规则）+ `normalize_stickies_v3` + schema split；知识库旧格式 `migrate_notes_legacy`（存 `notes.v1.json` → 轮转 → 先正文后索引） |
| 测试 | `cargo test` 用 `InMemoryBackend` + `FixedClock`，**不碰真实磁盘** |

关键约束：
- 新增持久文件必须走 `StoreBackend` trait，禁止直接 `fs::write`（破坏测试替身）
- 写前轮转是用户数据最后防线，**不可跳过**
- 损坏通道：主数据进恢复页；runtime 静默重建；知识库（notes/folders）进可恢复错误态——**绝不渲染假空态**
- v1 原件 `data.v1.json` 永不删除；schema 拆分留档 `data.pre-split.json` 已存在不覆盖
- 知识库写序不可反：先 `notes/<id>.md` 正文、后 `notes.json` 索引；索引 `contentHash` 校验不一致时以正文为准
- 图片外置：内联 `data:image` 由 `kb.rs` `extract_images` 抽到 `assets/<sha256>.<ext>`（先资产后正文）；渲染必须走 `rendering/asset-url.ts` + `convertFileSrc`，不可把绝对路径写进正文；assetScope 只覆盖默认数据目录
- 旧格式迁移存档 `notes.v1.json` 永不覆盖（回滚旧版本的唯一原件）
- 手动备份：导出不轮转、不写 `data.json` / `notes.json`；导入先算计划再落盘（dry-run 零写盘），落盘顺序 assets → 正文 → folders → 索引 → data，设置与便签不覆盖、本地独有绝不删；资源写入前先校验 hash，坏资源跳过
- 用户数据目录 `%APPDATA%\todo-list`，测试/脚本**禁止写入生产目录**
- 时间全链路本地语义字符串，零 UTC 换算（`models.rs` `DateTimeLocal`）
