# 06 · 知识库

## 设计

**容量**：≤5000 条。字段：标题 / 正文（Markdown）/ 标签 / 创建与更新时刻。

**文件树**：左栏一棵树同时展示文件夹与条目。文件夹存 `folders.json`（`KbFolder{id,name,parentId,order,pinned}`），条目用 `folderId` 引用（`null` = 未分类），条目自身的 `order`/`pinned` 与文件夹同一套排序语义。父文件夹必须存在、名称 ≤40 字，仅空文件夹（无条目引用且无子文件夹）可删；文件夹不能移动到自身或后代。同级顺序 dense 持久化，重开保持。展开态存 `localStorage('kb.tree.expanded')`；选中条目的祖先文件夹自动展开。搜索/标签过滤生效时左栏切换为扁平结果列表（每行带文件夹路径面包屑），清空过滤恢复原树与展开态，过滤态禁用拖拽与排序。

**备份恢复**：`notes.json` 每次覆盖写前轮转 5 份（`notes.json.bak-1~5`）；设置 → 备份与恢复 可列出槽位（含不可读项原因）并回滚，恢复前当前档先轮转进 `bak-1`；解析失败显示可恢复错误态，**不再静默空库**。手动备份（kb-storage-backup D3/D4）：可导出 `.kettdbackup` 单文件（含知识条目正文、文件夹与正文引用到的图片资源，缺失资源只计跳过不阻断）；导入先出预览计数、确认后才应用，按 id 合并——`updatedAt` 较新覆盖、本地较新跳过、同刻不同内容保留本地并生成「（导入冲突）」副本，本地独有绝不删；同一备份重复导入全部跳过。

**编辑器**：Tiptap WYSIWYG 单一即时画布（编辑即渲染）；标题就地编辑（Enter 存 / Esc 还原）；正文防抖 800ms 自动写回。详情面板排版见「写作区布局」。

**搜索**（纯本地，键入即渲染，kb-storage-backup S4 收窄）：
- 范围：条目标题 + 全部祖先文件夹名（沿 `parentId` 上溯，防环、深度上限 64）；不读正文、不匹配标签；标签筛选是独立的另一条过滤，二者互不影响
- 打分：标题完全相等 100 / 前缀 50 / 包含 20；文件夹名完全相等 8 / 前缀 4 / 包含 2（取所有祖先中的最高分，不累加）
- 排序：分数降序，同分按更新时间倒序，再同按标题升序；空查询 = 全量按更新时间倒序
- 返回有序 id 数组（同一 id 只出现一次）；前端持全量条目，按 id 映射并补全未命中项

**直达热键**：默认 `Alt+Shift+K`，唤起主窗口并跳转知识库（`#/kb`）；可在设置页改绑或清空（清空 = 不注册）；与其余四个全局热键互斥，被占用时保留旧绑定并提示「这个快捷键已被其他功能占用，换一个组合」，注册失败回滚旧键、不阻塞启动。

**标签**：入库归一（去空白/去空项/去重）；筛选为前端过滤，点同标签取消。

**结构操作**（单树 / 右键 / 拖拽，见 `specs/knowledge-base/workspace`）：
- 右键菜单：节点（新建文件夹 / 新建文件 / 重命名 / 删除 / 置顶 / 取消置顶 / 移动到…）、树空白区（新建文件夹 / 新建文件 / 展开全部 / 收起全部）、输入框编辑菜单（剪切 / 复制 / 粘贴 / 全选，粘贴不可用时置灰）；Esc / 点击外部关闭，↑↓ / Enter 键盘可达；正文编辑器不挂自定义菜单
- 拖拽：拖到文件夹行中部 = 移入（悬停 600ms 自动展开）；拖到同级行上下边缘 = 插入线排序；拖拽落库后刷新/重开顺序保持；自身/后代预判拒绝，过滤态与置顶区禁用拖拽，外部文件拖入不触发导航
- 移动：右键「移动到…」与拖拽等效，失败时展示后端中文文案（如「不能移动到自身或子文件夹」「文件夹不存在」）
- 置顶：文件夹与条目均可置顶/取消置顶；置顶对象在树顶「置顶」快捷区展示且原位置保留；置顶优先于手动 `order`；置顶区只读（不可拖拽）
- 新建即命名：新建文件夹/条目后焦点落名称输入并全选，未改名离开保留默认名

**条目动作**：贴到桌面（创建知识便签）/ 删除（两步确认；被任务引用时提示「N 处引用将悬空」）。详情页不提供「所属文件夹」下拉与「转为待办」入口，移动统一走拖拽或右键「移动到…」。

**任务联动**：任务详情「关联资料」（选条目整体替换 kbRefs；点「+ 关联条目」打开条目选择器）；条目删除后任务侧引用显示「📎 已失效」。

**Deep Link**：`#/kb?id={itemId}` 自动选中并展开祖先后按需定位（支持页内 hashchange）。左清单可折叠，状态持久化。

## 写作区布局

详情面板是宣纸面 + 暖墨字的纸面，正文是纸面中央的手稿栏：内容列水平居中、左右留白随面板宽度成比例增长（有下限），标题 / 标签 / 工具栏与正文同列左缘对齐。只做布局与留白，不改主题、行高、配色 token；正文列宽上限、字号、字距改由用户档位控制（见下节「阅读偏好」）。

| token（定义在 `.kb-detail`） | 值 | 作用 |
| --- | --- | --- |
| `--kb-measure-cap` | `96ch`（舒适）/ `112ch`（宽敞） | 正文列宽上限，随设置项 `readingMeasure` 在两档间切换（CJK 约 48 / 56 字/行；默认舒适） |
| `--kb-gutter` | `clamp(20px, 4vw, 64px)` | 左右最小留白：窄面板 20px 起，宽窗随面板增长、64px 封顶 |
| `--kb-bottom` | `max(64px, 26vh)` | 底部写作留白：末行可滚到视口中部以上，光标不贴视口底边 |
| `--fs-reading` | `8`–`20`px 七档 | 正文与 H1–H6 的字号基数，随 `readingSize` 切换（默认 16px） |
| `--ls-reading` | `0`–`0.09em` 七档 | 正文与标题的字距，随 `readingTracking` 切换（默认 0） |

结构：`.kb-detail`（纸面 + **唯一滚动容器**，负责 gutter/bottom 留白与 `scroll-padding-bottom`）> `.kb-detail-inner`（`width: min(100%, var(--kb-measure-cap))` + `margin-inline: auto`，工具栏/标题/标签/正文自动同列）> `.kb-detail-body` > `.kb-editor-content`（行高 1.85 / H1–H6 阶梯按 `--fs-reading` 等比缩放）。正文不再单独限宽（旧 `.kb-editor-content{max-width:76ch}` 已移除，避免与标题左缘错位）。

两档上限行为（列宽 = 可用宽与上限取小，多出的宽度对称平分到两侧）：
- 宽窗（>1440px）：列宽撞到当前上限（舒适 96ch ≈ 48 字/行、宽敞 112ch ≈ 56 字/行），继续加宽只增留白不加行宽
- 标准窗（≈1100px 窗口，左树展开）：面板约 652px，未到上限，列宽随面板宽度走
- 窄面板（<720px）：列宽 100%、侧留白 20px、面板无横向滚动条

量算口径：详情面板宽 = 窗口宽 − 全局侧栏（168px；窗口 ≤1040px 时 56px）− `.kb-view` 左右 padding 32px − 左树列（展开 232px / 折叠 96px）− 栅格 gap（16px / 8px）；列宽 = min(面板宽 − 2×`--kb-gutter` − 滚动条预留, `--kb-measure-cap`)，多出的宽度对称平分到列两侧。`96ch` / `112ch` 的 ch 由 **chrome 正文字号（16px）**解析，所以切阅读字号不会改变列宽像素，只改变每行字数。

溢出：宽表格在 tiptap 生成的 `.tableWrapper` 内横向滚动；`pre` 自身横向滚动；图片 `max-width:100%`；长 URL / 无空格长串只对正文文本元素 `overflow-wrap:anywhere` 折行（标题不折）。

**已知限制（真机待验，2026-11-16）**：当前仅完成静态层核对（`npx tsc -b` + `cargo test` + 契约测试），未做真机截图与 WebView2 实际渲染，待验项：两档上限（96ch / 112ch）在 1100 / 1440 / 1920 窗口下的实际留白与左缘对齐、滚动到底时底部尾 padding 是否保留（Chromium 行为，需真机确认）、长文滚动后左上折叠钮随内容滚出视口的行为是否可接受。

### 阅读偏好（字号 / 字距 / 列宽上限）

正文的阅读密度由三个设置项控制，都存在 `Settings` 里、随 `store-changed` 跨窗同步，且**只作用于 `.kb-detail` 子树**（便签窗标题与正文不受影响）：

| 设置字段 | 档位 | 默认 | 落点 |
| --- | --- | --- | --- |
| `readingSize` | 8 / 10 / 12 / 14 / 16 / 18 / 20（px） | 16 | `--fs-reading`，正文与 H1–H6 按倍数联动 |
| `readingTracking` | 索引 `0..=6` → `0`–`0.09em`（步长 0.015em） | 0 | `--ls-reading`，正文与详情标题 |
| `readingMeasure` | `comfortable`（96ch）/ `wide`（112ch） | `comfortable` | `--kb-measure-cap`，`.kb-detail-inner` 的宽度上限 |

链路：设置页 `.seg` 按钮 → `patch({ readingSize | readingTracking | readingMeasure })` → 后端 `normalize_reading_*` 白名单兜底（越界回默认值，不报错）→ 前端 `applyReadingPrefs()` 写 `document.documentElement.dataset.reading*` → `kb.css` 里 `:root[data-reading-*='…'] .kb-detail` 覆盖局部 CSS 变量。档位表前后端各一份（`models.rs` 的 `READING_SIZES` / `READING_TRACKING_MAX` / `READING_MEASURES` 与 `lib/reading-prefs.ts`），改一处必须同步另一处。

不写在 `documentElement` 上直接覆盖 `--fs-reading`：`prosemirror.css` 的 H4–H6 规则不带 `.kb-detail` 前缀，全局覆盖会把便签窗标题一起放大。

### 链接

链接只认 `http` / `https` / `mailto` 三种协议（`lib/link-url.ts` 的 `isSafeLink`），其余协议既不转换也不可点。

| 入口 | 行为 |
| --- | --- |
| 输入 `[@文本](https://…)` | 键入 `)` 时 InputRule 就地转成链接，可见文字剥掉 `@`；纯 `[文本](url)` 不转换（避免把非超链接的方括号吃掉） |
| 粘贴 | 剪贴板**整段**匹配同一语法才转换，混在长文里的不处理 |
| `/link` 或 `Ctrl/Cmd+K` | 插入 `[@文本](https://)` 模板并选中「文本」占位，直接键入即替换 |
| 点击已有链接 | 在链接下方弹一条内联输入条（预填 href，Enter 确认、Esc 取消、清空即移除、点条外关闭），不再是居中模态弹窗 |
| `Ctrl/Cmd+点击` | 交给系统浏览器打开，应用窗口不导航 |

编辑区链接色走 `--link` 令牌（亮 `214 70% 40%` / 暗 `210 75% 68%`，对纸面 6.03:1、暗底 7.50:1），带下划线，与阅读态 `.kb-md-render a` 同一取值。

落盘归一化：`saveNow()` 在 `getMarkdown()` 之前把普通段落里残留的 `[@文本](url)` 转成 `[文本](url)`（代码块与行内代码内跳过），所以 `notes/<id>.md` 里不会出现 `[@`。

### 宣纸面与令牌映射

详情面板的纸与墨定义在 `.kb-detail` 上；颜色映射的目标态见 `openspec/changes/refine-frontend-visual-language/design.md` §4.6（归档后看 `openspec/specs/visual-language/spec.md`）。当前落地现状：

| 变量 | 亮色 | 暗色 | 说明 |
| --- | --- | --- | --- |
| `--paper` / `--paper-deep` | 暖纸白（保留原值） | `--background` / 保持暖值 | 暗色纸面交给共享令牌，避免暗色主题里出现一块亮纸 |
| `--ink-1` | 暖墨（保留原值） | `--foreground` | 正文墨色 |
| `--ink-2` | 暖次级墨（保留原值） | `--muted-foreground` | 标签、元信息 |
| `--ink-3` | `--muted-foreground` 75% | 同左 | 弱化文字（标签删除钮、任务清单已勾行） |
| `--seal-track` / `--seal-ink` | `hsl(var(--seal))` | 同左 | 朱砂：前者用于 1px 结构线（焦点下划线、印章点、删除确认描边），后者用于文字/图标 |
| `--seal-soft` | `hsl(var(--seal) / 0.12)` | 同左 | 朱砂底纹（当前块高亮） |
| `--line-warm` | `hsl(var(--border))` | 同左 | 结构线统一走共享边框色 |

纸纹（`feTurbulence` SVG）与 inset 阴影保留，它们不是色值：暗色下纸纹 opacity 降到 0.04、inset 阴影改纯黑 18%，避免暗色里泛白。

**与 §4.6 映射表的偏差（2026-11-15 落地时确认）**：`--paper` / `--paper-deep` / `--ink-1` / `--ink-2` 四项在**亮色**仍保留原暖值，没有换成 `--background` / `--secondary` / `--foreground` / `--muted-foreground`。原因是映射到共享冷灰后宣纸的暖调辨识度会丢，「同一屏里只有知识库是一张宣纸」的视觉承诺随之失效；改成亮色保暖、暗色接管，两个主题都不丢语义。

**对比度（脚本按 WCAG 相对亮度计算，2026-11-15）**：亮色正文 `--ink-2` 5.05:1、`--ink-1` 9.99:1；暗色正文 `--muted-foreground` 6.62:1、`--foreground` 16.55:1，均 ≥4.5:1。`--seal` 亮色 4.34:1、暗色 3.72:1，**不足 4.5:1**——它只用于结构元素与图标，按 WCAG 1.4.11 非文本对比 ≥3:1 适用；若将来拿它当正文字色需重新取值。

| 存储 | `notes.json`（元数据索引）+ `notes/<id>.md`（正文，先正文后索引）+ `folders.json`（文件夹树）+ `assets/<sha256>.<ext>`（图片），均与 `data.json` 物理隔离；旧格式首启迁移，原件 `notes.v1.json` |
| 测试 | `src-react/test/kb-tree.test.mjs`（单树/落点纯函数）+ `src-react/test/md-fidelity.test.mjs`（渲染保真） |

关键约束：
- ⚠️ AI 混合检索已于 2026-11-07 整体摘除（ai/ 模块删除、命令 59→55），**不要重新引入 AI 栈**；搜索保持纯本地
- 文件夹命令统一走 `update_folder(id, name?, parent_id?, order?, pinned?)`：改名 / 移动 / 排序 / 置顶同一入口（`rename_folder` 已删除，当前命令总数 71 条，契约以 `api.ts` / `docs/ARCHITECTURE.md` 附录 §2 为准）
- 搜索匹配范围与打分只改 `kb.rs` 一处（标题 + 祖先文件夹名；正文 / 标签不参与）；前端 KbView 持全量数据按返回 id 重排
- 知识便签同步：`store-changed` 事件触发重拉；焦点在本窗时跳过防覆盖
- 删除条目后任务侧 kbRefs 悬空，前端展示「📎 已失效」而非静默丢弃
- 图片：正文只存相对引用 `assets/<sha256>.<ext>`；渲染经 `rendering/asset-url.ts` + `convertFileSrc`，打包配置 `tauri.conf.json` 的 `protocol.asset` 窄 scope 只覆盖默认数据目录，`KETTD_DATA_DIR` 自定义目录下图片不显示（已知限制）
- 知识点附件（`kbRefs`）与知识库 body 分属 data.json / notes 两套存储，恢复 notes 不影响任务侧引用
- 详情页无归属下拉 / 无「转为待办」；移动只经拖拽与右键「移动到…」
- 扩展动作（如新增「导出条目」）走 `commands.rs` 新增命令 + `api.ts` 封装 + `V2-API.md` 同步 + parity 门禁
